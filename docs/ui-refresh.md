# Workspace UI

Today, Menu, Preferences and Settings share Geist typography, neutral light and dark surfaces, sage selection states, 44px controls and visible keyboard focus. Styles live in `src/app/workspace.css`; shared primitives remain in `src/components/ui.tsx`.

Today combines a meal-choice fit summary with plate ideas and a full-photo dish gallery. Native CSS columns arrange mixed card proportions without a layout library. Station, dish name and the current rating sit over a bottom gradient. The gallery uses three columns on desktop, two on tablets and one on phones. Selecting a dish opens an inline inspector with community notes and a separate review editor. The inspector stays beside the scrolling list on larger viewports and replaces it on phones. Star ratings support keyboard selection, save states and focus restoration.

Menu filters the dishes at a selected station. Its first dish fills a wide feature photo. The remaining dishes use staggered photos with varied aspect ratios and names over the photos, matching the scale and typography of Today cards. Selections with three remaining dishes use three columns on wide screens; larger selections use two columns. Cards keep their own heights instead of stretching to shared row edges. Single- and two-card selections reduce the column count; phones use one column. Missing photos use a neutral placeholder. Small screens place station controls and the posted-menu action before the dishes. The public sample uses a single menu date; authenticated screens retain date navigation.

Preferences uses one instruction field and two grouped summaries: Eating pattern and Ingredients. Review notes stages explicit diet, goal, favorite, exclusion and allergy clauses; unrecognized instructions must be clarified before saving. Save preferences commits the reviewed profile and refreshes recommendations. Cancel restores the saved profile. The saved state hides the footer actions; editing reveals Cancel and Save. Existing dislikes and temporary restrictions are preserved. The parser runs locally without a model or network request; it does not claim to understand arbitrary instructions.

Appearance uses compact Light, Dark and System previews in the public demo. An always-visible digest panel shows current sample breakfast and lunch picks, without delivery controls. Settings shares the rounded panel borders, connected dividers and type scale of Preferences. Panels align at the top and size to their content. Appearance changes apply immediately. Email delivery uses an explicit save and reveals scheduling fields when enabled. Account changes retain the existing verification flow. Main navigation returns to the top, including repeat taps on the active tab. Section anchors retain their normal behavior.

Transitions affect local state and carousel movement. Reduced-motion settings disable these transitions. No animation or UI library was added.

For guest behavior and fit calculation, see [Public demo](public-demo.md). Generated food images and the sample poster are illustrative assets; recipe tags are sample data, not verified café ingredients.
